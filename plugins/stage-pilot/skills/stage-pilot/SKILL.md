# stage-pilot

워크플로 단계마다 **어느 플러그인을 어떤 순서로 쓰고, 어디서 멈춰 승인받는가**를 `references/stage-map.json` 한 곳에서 읽어 안내·수행한다. 이 파일은 통합 가이드의 `#selection`(플러그인 선정)과 `#stage-map`(단계별 지도), 시나리오 가이드 2종의 지도를 옮긴 것이다 — 가이드를 고치면 이 파일도 함께 고친다.

## 상태

- 상태 파일: 대상 프로젝트의 `.claude/stage-pilot/state.json` (`profile`, `stage`, `auto`, `decisions`, `history`). 없으면 훅은 아무것도 하지 않는다(다른 프로젝트를 방해하지 않기 위해).
- 조회·변경은 항상 스크립트로 한다. 상태 JSON을 손으로 고치지 않는다.
  - `node "${CLAUDE_PLUGIN_ROOT}/scripts/stage.js" status` — 현재 단계 카드
  - `… plan [stage]` — 그 단계에서 도구로 호출할 항목(`invoke`)과 안내만 할 항목(`other`)
  - `… set <profile> [stage] [--auto]`, `… next`, `… auto on|off`, `… log "<결정>"`
- 프로필: `default`(통합 가이드), `fastapi-default`, `g6`. 단계 id는 `pre`, `0`, `1` … 또는 묶음(`4-7`, `7-11`).

## 제안 모드 (기본, `auto` 꺼짐)

요청이 단계 작업이거나 세션에 `[stage-pilot]` 안내가 있으면:

1. 현재 단계 카드(`status`)를 근거로 **주 플러그인 → 보조 → 조건부(조건 충족 시만)** 순서로 제안한다. 조건부는 조건을 한 줄로 확인하고 맞을 때만 권한다.
2. 요청이 다른 단계의 일이면(훅이 알려 줌) 첫 줄에 "이 요청은 N단계(제목), 현재는 M단계"처럼 **두 단계 번호를 모두** 밝히고, 그 사이 건너뛰는 단계와 위험을 알린 뒤 사용자가 고르게 한다. 사용자가 단계 지도에서 위치를 바로 찾을 수 있게 하기 위해서다. 건너뛰는 것 자체를 막지는 않는다.
3. 미설치 플러그인은 설치 명령을 보여 준다. `/plugin install`·`/plugin marketplace add`·`/mcp`는 사용자만 실행할 수 있다.
4. 실행은 하지 않는다. 실행은 `run`, "N단계 진행해줘" 같은 명시적 요청, 또는 자동 승인 모드일 때만.

## 수행 모드 (`run [stage]`, 명시적 요청, 또는 자동 승인 모드의 단계 작업 요청)

1. `plan [stage]`으로 호출 항목을 받는다.
2. `invoke`의 항목을 **실제 도구 호출로** 처리한다. 같은 일을 직접 해 버리고 플러그인 호출을 생략하지 않는다 — 이 플러그인의 목적은 가이드가 정한 플러그인이 실제로 쓰이게 하는 것이다.

| type | 방법 |
|---|---|
| `skill` | Skill 도구로 `ref` 호출 (예: `superpowers:test-driven-development`) |
| `agent` | Agent 도구, `subagent_type` = `ref` (예: `feature-dev:code-explorer`). 프롬프트에 대상 경로·이번 단계 목표·`note`를 넣는다. 서로 독립인 에이전트는 한 메시지에서 병렬로 |
| `command` | Skill 도구로 `ref` 호출 (플러그인 명령은 `플러그인:명령` 이름으로 노출됨), `args`를 인자로 |
| `shell` | Bash로 실행. 파일을 바꾸는 명령은 제안 모드에서는 먼저 보여 주고 확인 |
| `user` | 실행하지 않고, 사용자가 입력할 명령을 그대로 보여 준다 (`/ralph-loop`, `/plugin`, `/mcp`, `claude mcp add` 등) |

3. `when`(조건)이 붙은 항목은 프로젝트를 보고 조건을 판정한다. 충족하면 호출하고, 충족하지 않으면 호출하지 않고 `log "조건 불충족: <ref> — <근거(예: 도메인 1개)>"`를 남긴다. 판정 근거 없이 건너뛰지 않는다.
4. 호출할 수 없는 항목(플러그인이 없음, 프로젝트 스킬 `fastapi-layer-slice`·`layered-slice`가 아직 없음)은 건너뛰지 말고 **같은 목적을 직접 수행한 뒤** `log "대체 수행: <ref> 없음 → <한 일>"`로 남긴다. 프로젝트 스킬이 없으면 만들 단계(default 5단계, fastapi-default 11단계)를 함께 알린다.
5. 에이전트·리뷰 결과가 고칠 거리를 내면 그 단계의 목표 범위 안에서 실제로 고친다(보고만 하고 끝내지 않는다). 리뷰 지적은 `superpowers:receiving-code-review` 기준으로 검증한 뒤 반영한다.
6. 끝나면 `done`(완료 기준)을 실제 출력(테스트 결과, 산출물 경로)으로 확인한다.

## 승인 지점

- **제안·수행 모드(`auto` 꺼짐):** 승인 지점(`approval`)에 닿으면 멈춘다. 결과를 요약하고 결정할 항목을 질문으로 제시한 뒤 턴을 끝낸다.
- **자동 승인 모드(`auto` 켜짐):** 멈추지 않는다. 아래 원칙으로 결정하고, 결정마다 `log "<결정과 근거>"`로 남긴 뒤 계속한다. 질문(AskUserQuestion 등)을 하지 않는다.

### 자동 결정 원칙 (가이드의 기본안)

| 결정 | 자동 선택 |
|---|---|
| 규칙 카드와 실제 동작이 다름 | 현재 동작을 계약으로 고정하고 "버그 후보"로 기록 (리팩토링 중 동작 변경 금지) |
| 리팩토링 우선 도메인·순서 | 위험도 표에서 커버리지 낮고 변경 잦은 것 먼저. 동률이면 의존이 적은 것 |
| 설계안 선택 | 기존 구조와 차이가 가장 작은 안(architecture-critic이 과잉 설계로 지적하지 않은 안) |
| 응답 필드·입력 허용 범위가 바뀌는 수정 | 하지 않음 — API 계약 변경은 별도 작업으로 기록 |
| 보안 발견 | 두 도구가 함께 찾았거나 근거 코드가 명확한 것만 수정, 나머지는 기록 |
| 남은 리뷰 이슈 | 이번 단계 범위 안이면 수정, 밖이면 기록 |
| 커밋 | 로컬 커밋만, 단계·논리 단위로 |

### 자동 승인 대상이 아닌 것 (자동 모드에서도 하지 않음)

- 원격 저장소 작업(push, PR), 저장소 밖 파일 수정, 데이터·파일 대량 삭제
- `user` 항목(`/plugin`, `/mcp`, `/ralph-loop` 등) — 실행하지 않고 log로 "사용자 실행 필요"를 남김
- 테스트가 실패한 채로 다음 단계로 넘어가기 — 고치지 못하면 그 지점에서 멈추고 보고

## 단계 완료와 이동

- 제안·수행 모드: 완료 기준 확인 후 사용자에게 다음 단계로 갈지 묻는다. 동의하면 `next`.
- 자동 승인 모드: 완료 기준을 확인했으면 `log`로 남기고 `next`. `run … --through <stage>`가 주어졌으면 그 단계까지 같은 방식으로 이어서 수행한다.
- 확인하지 못한 기준은 "미확인"으로 남기고 넘어가지 않는다.

## 다른 규칙

- `ralph-loop`는 첫 결과물이 승인된 뒤에만, `--max-iterations`를 붙여 사용자에게 제안한다. 설계 결정·보안 패치에는 쓰지 않는다.
- `ponytail`의 점검 명령은 보고 전용이다. 지적은 검증 후 반영하고, 계층을 새로 만드는 구간(default 5·6, fastapi-default 4~7, g6 7~11)에서는 `/ponytail lite`를 권한다.
- g6 프로필의 `code-modernization` 명령은 저장소 밖 `~/work/g6-analysis`에서만 실행한다(`workspace_note`).
- `context7`은 질의가 외부로 나가므로, 사용자가 문서 조회를 허용했을 때만 쓴다.

## 응답 형식

제안:
```
■ <N>단계 — <제목>
추천: 주 <…> · 보조 <…> · 조건부 <플러그인(조건)>
실행할 것: 1) … 2) …
멈출 곳: <승인 지점>
(미설치: <설치 명령>)
```

수행 후:
```
■ <N>단계 수행 결과
호출한 플러그인: <ref> → <결과 한 줄> …
변경: <파일·테스트>
자동 결정: <log 한 내용> (자동 승인 모드일 때)
완료 기준: <충족/미확인>
```
